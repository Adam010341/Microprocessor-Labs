# Lab 5 Advanced：`count_primes` 交接說明

這個資料夾是 Lab 5（Mixing with C）Advanced 題。

- `count_primes.S`：速度優化版，**已交 judge：AC，20 組總共 1,005,360 cycle，score 30**（2026-10-13 排行榜；參考程式約 1,000,000，速度 −0.53%）。全範圍單組約 14.6 萬 cycle，上一版約 2.4 億。程式大部分是產生器展開的重複程式碼，所以有 3700 多行。
- `short/count_primes.S`：**同一個演算法的短版**（約 190 行指令），用迴圈代替展開，比較好讀；cycle 約是長版的 2 倍（全範圍 308,781），還沒交過 judge。想理解演算法請先看這個，見下方「短版」。

## 題目

```c
extern unsigned int count_primes(unsigned int n, unsigned int m);
```

回傳 `n ≤ p ≤ m` 的質數個數，`n`、`m` 都是 16 位元無號數。PIC18F4520，XC8 v4.00 + pic-as，只交 `count_primes.S`（不含 `main.c`）。

## judge 的規則與已知行為

- 線上 judge 用自製的 C 模擬器（比 MPLAB 快約 900 倍），20 組測資（14 固定 + 6 隨機），每組答對 1 分；全對之後依 cycle 數給速度分：
  `Score = 10 × (1 − (R − 1) / (1600 − 1))`，`R` = 你的 cycle ÷ 參考程式的 cycle。
- **同一次執行裡連續呼叫 `count_primes` 20 次**，所以所有狀態都要在函式開頭重設（之前 `count` 沒清零，答案一路累加）。
- 呼叫時 BSR 不保證是 0：每個指令都要明寫 `, a`（組譯不能有 `(1522)` 警告）。
- 不能寫死任何 RAM 位址：參數用 `_count_primes$0`（n）、`_count_primes$1`（m），回傳值寫到 `_count_primes$0`（低位）和 `(_count_primes$0+1)`（高位），變數用 `PSECT` + `DS`。
- judge 支援 `TBLRD`；它會回報函式改了哪些暫存器（例如 `TBLPTRL`、`TABLAT`、`FSR0H`…），並自動復原，只是資訊。
- 測資名稱（看得到的部分）：tiny `(1,10)`=4、two-only `(2,2)`=1、no-primes `(24,28)`=0、mid-range `(100,200)`=21、full-range `(1,65535)`=6542，另有 high-window、rand-wide、rand-narrow、rand-cent、rand-full 等隱藏測資。**`n == m` 會出現**，`n` 可能是 0 或 1。
- HackMD 範例畫面裡，別人通過的程式全範圍約 1.4 億 cycle、baseline 寫 1,000,000。

## 目前的演算法（`count_primes.S`，速度優化版）

`count_primes.S` 是 `tools/gen_count_primes.py` 產生的（`python3 tools/gen_count_primes.py > count_primes.S`）。要改請改產生器，因為大部分是展開的直線程式碼（每個質數一段標記程式、一段展開的計數）。

只篩奇數，每段 255 個奇數：

- 全域索引 `g` 對應奇數 `2g+1`；第 `K` 段是 `g = 255K … 255K+254`，放在 `arr` 的位置 1…255（位置 = 段內索引 + 1，位置 0 不用）。`arr` 是整個 bank 1（`udata_bank1` 256 bytes），所以一定對齊 256，`FSR2L` 從 255 加過頭時剛好在段尾進位。
- 每格 `00h` = 可能是質數，`FFh` = 合數。標記一律用 `setf`，計數時把一段的值相加：8 位元總和 = −（合數個數）。
- **3、5、17 不用標記**：255 = 3·5·17，所以這三個數的倍數在每一段的位置都一樣（共 127 格）。每次呼叫開頭用展開的 `setf`/`clrf` 把整段填好之後，這 127 格一直是 `FFh`，計數也直接跳過，只看其他 128 格（banked 直接定址 `addwf BANKMASK(arr+k), w, b` + `clrf`，每格 2 cycle，順便清掉給下一段用）。
- 其餘 50 個質數（7…251）在 `nxt[]`（`udata_bank2`，50 bytes）記住「下一個倍數在下一段的索引」。標記迴圈只有 `setf INDF2 / addwf FSR2L / bnc`（小質數展開 8 次，每次標記約 3.1 cycle）；`FSR2L` 進位時留下的值就是下一段的起點，直接存回 `nxt[]`，換段不用重算任何東西。
- 質數 `p` 在 `p²` 所在的段 `Kp` 才開始標記（起點就是 `p²`）。程式是一串 `st_p` / `run_p`：`st_p` 檢查 `p` 這一段要不要啟動，`run_p` 用已啟動的質數（`call blk_<最大的>`，由大到小一路標到 7）標記這一段、計數、換下一段。`p² > m` 的質數永遠不會啟動。
- 第一段 `K0` 若已經在 `Kp` 之後，起點用乘法器算一次（不用除法）：`c = 255 mod p`、`F = ⌈c·65536/p⌉`，`q = ⌊K0·c/p⌋ =（K0·F_hi + hi(K0·F_lo)）的高位元組`（`K0 ≤ 128` 時保證正確），`r = K0·c − q·p`，起點索引 `= (h − r) mod p`，`h = (p−1)/2`。產生器的常數已經用 Python 對所有 `p` 和 `K0 = Kp+1 … 128` 窮舉驗證過。
- 範圍：`n < 2` 改成 2，`m < n` 回傳 0；`g_n = n >> 1`（第一個 ≥ n 的奇數），`g_m = (m−1) >> 1`（最後一個 ≤ m 的奇數），`g_m < g_n` 表示範圍裡沒有奇數。`K = g div 255`、段內索引 `= g mod 255`（`256·gH + gL = 255·gH + (gH+gL)`，最多修正一次）。
- 第一段若不是最後一段，先把 `n` 之前的格子標成合數，再用展開的整段計數；最後一段用一般迴圈只數到 `m`。
- 2、3、5、17 本身不會被篩出來（2 不在奇數表，3/5/17 落在固定合數格），開頭直接檢查是否在 `[n, m]` 裡再加上去。
- 呼叫開始時存 BSR、結束前還原；所有狀態（`count`、`arr`、`nxt[]`、段號）每次呼叫都重設。

## 已修過的坑（優化時不要再踩）

- 無號比較一律看 Carry（`subwf` 後 `bnc`/`bc`），不要用 `bn`/`bnn`。
- 16 位元減法用 `subwf` + `subwfb`，不要用會改到被減數的二補數寫法。
- 標記用 `bsf`，不要用 `incf`（同一格被標兩次會讓 bit 0 變回 0）。
- 每個質數開始時清 `temp2_h`；每段重設 `TBLPTR`；找起點是跟本段的 `lo` 比，不是跟 `n` 比；標記上界是 `hi`，不是 `m`。
- `lo` 的低位元組為 0 時，`hi = lo + 255` 要用真正的 16 位元加法。
- `x += p`、`start += p` 都要檢查超過 65535。
- （這一版）`arr` 必須剛好是整個 bank 1，才會對齊 256；不要在 `udata_bank1` 再放別的變數，也不要把 `arr` 改小。
- （這一版）用 banked 定址的地方（`arr` 的計數、`nxt[]`）前面都有 `BANKSEL`；`seg_end` 計數前切到 `arr` 的 bank，回來前切回 `nxt` 的 bank。
- （gpsim）gpasm 會把奇數個 byte 的 `DB` 行補一個 0，pic-as 不會；`gpsim_test.py` 會先把連續的 `DB` 行接起來（上一版的質數表第一行 19 個數，沒接起來會在 67 後面多一個 0）。

## 還可以再快的地方（效益都不大）

1. 7、11、13 改成「每個相位一段展開的 `setf BANKMASK(arr+k), b`」，只標在不是 3/5/17 倍數的格子：7 每段從 ~118 cycle 降到 ~35 cycle。三個加起來全範圍大約再省 2 萬 cycle（約 13%），代價是每段要依相位分派（7/11/13 種）。
2. 小範圍（例如 `n == m` 在 60000 以上）主要花在第一段啟動 50 個質數（每個 ~25 cycle）和整段標記；很窄的範圍可以改用試除，但 judge 的速度分在 R 接近 1 以後幾乎不變，應該不值得。
3. 排行榜第一名 20 組總共 678 cycle（平均每組約 34 cycle，含 call/return），這只可能是查表：把「≤ x 的質數個數」事先算好放在 Flash（例如每 16 個數存一個前綴計數 + 一個 byte 的奇數質數 bitmap，約 20 KB），答案 = Π(m) − Π(n−1)。指令只要幾十行，但檔案要多一大段數字表，演算法也變成「查答案」而不是篩法。score 已經是 30（滿分），查表只會影響排名，不影響分數。

## 短版 `short/count_primes.S`

跟長版是同一個想法，差在沒有展開、也沒有 3/5/17 的固定格：

1. `n < 2` 改成 2；`m < n` 回傳 0；`n == 2` 先把 2 算進去（偶數不篩）。
2. 只看奇數：`g = (v−1)/2`。第一個 ≥ n 的奇數 `g = n/2`，最後一個 ≤ m 的奇數 `g = (m−1)/2`，再用 `half_div255` 換成「第幾段、段內第幾格」。
3. 清空 `arr`；第一段若不是最後一段，先把 `n` 之前的格子標成合數。
4. 每一段（`segment:`）：
   1. 把 `p²` 已經到了的質數加進 `prm[]`（`add_prime`）：剛好在這一段就從 `p²` 開始；如果第一段已經超過 `p²`，用乘法器算第一個倍數的位置（不用除法）。
   2. 對 `prm[]` 裡每個質數：`FSR2L = 下一個倍數的格子`，一直 `setf INDF2`、`FSR2L += p`，直到 `FSR2L` 進位（超過段尾）；進位後 `FSR2L` 剩下的值就是下一段的起點，存回 `prm[]`。
   3. 數這一段：每格是 `00h` 或 `FFh`，全部加起來 = −（合數個數），質數個數 = 格數 − 合數個數。不是最後一段就邊數邊清成 0，換下一段。
5. 回傳總數。

長版多做的兩件事（所以快一倍，但長很多）：3、5、17 的倍數在每段的位置都一樣，只在開頭標一次、計數時跳過；每個質數、每一格的計數都由產生器展開成直線程式碼，省掉迴圈的判斷。
